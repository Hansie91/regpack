# Traceability (spec 14.4)

Maps requirements R1-R14 and invariants I1-I10 to named evidence. Checked by the gate
`Gates traceability` (`regpack-tools`), which CI runs after the build.

- A row is *due* when every plan in `closes_in` is listed in `exited_plans`; otherwise it is open and may have no evidence.
- A due row needs at least one counting evidence: the artefact exists, records a pass, is not `NONE`, and is not interim.
- Interim means: the row is I1, I2, I9 or I10 and the evidence `store` is not `REALSTORE`, with one exception: for I1 and I10 a `REALFILES` or `REALSTANDBY` line is not interim (for I2, I9 and every other row neither label ever counts). Consistency-only golden cases never count.
- Three labels name real-environment evidence (P-SEALED half; P-WORM at P3b2). `REALFILES` lines name tests that run in the build jobs on Linux and Windows against the real file system of the runner (P-SEALED over two directories); the build jobs run `--realstore skip`, which evaluates them. `REALSTORE` lines name tests that run only in the CI job `ledger-pg`, against a real PostgreSQL server. That job evaluates only these lines (`Gates traceability --realstore only`); the build jobs run `--realstore skip`, where they are not looked up and never count. `REALSTANDBY` lines name tests that run only in the CI job `ledger-durability`, against a primary with a quorum synchronous standby. That job evaluates only these lines (`Gates traceability --realstore standby`), where a due row without a `REALSTANDBY` line is open, not a problem; `skip` and `only` do not look them up and they never count there.
- A due I1 or I10 row needs a passed `REALSTORE` line in the job `ledger-pg` (spec 14.1: real PostgreSQL and both evidence profiles), where `REALFILES` lines are not evaluated. In `skip` mode a due row of I1, I2, I9 or I10 that has a `REALSTORE` or `REALSTANDBY` line and no counting line is reported as `REALSTORE_DEFERRED:<row>`, information and not a problem.
- `TEST` refs are `fully.qualified.Class#method` (the concrete test class of the adapter's module); renaming a cited test without updating this file fails the gate.
- The `closes_in` column is a proposal for the owner (invariants follow the spec 14.4 list, requirements follow the section 3 and 16 mapping).
