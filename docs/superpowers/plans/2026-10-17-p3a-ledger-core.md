**Status.** DRAFT for owner approval (AP-1). Nothing is built; writing this plan created only this file. Work branch `p3a/ledger-core` exists, created from `main` at `e685b7f` (P0, P1a and P2a merged). The P1a sign-off and the spec freeze are not recorded (section "Departures").

**Goal.** Put the ledger on real PostgreSQL 18 with its constraints proven by the real store: a schema design that the owner reviews before any SQL is written; the decision-context circuit epoch (mechanism and ledger contract; P2a open item 1 closes only when the epoch is durable, see D-L1); the TRN, report-subject, report-version and delivery-in-PREPARED data path as one unit of work; plain-SQL migrations; the real `LedgerStore` adapter bound to the same contract suites as the in-memory adapter; fenced leases, the partial unique in-flight index and the head compare-and-set exercised on the real store in CI; and the capacity information that the L-4 FAIL needs. The evidence tier, keys, signer, state machine and queues are P3b to P3d.

**Split decision (P3a now; P3b, P3c and P3d later).** The spec 16 row has about seventeen deliverables and two internal checkpoints. The split follows the dependencies of the plans that wait for P3 (P7a needs checkpoint 1, P8 and P10a need checkpoint 2) and puts the work that can only be verified on a real server into the slice that plans for it.

## Decisions made by this plan (reversible, with reasons)

- **D-L1 INTERP-3 option A, a circuit epoch in `DecisionContext`.** It keeps the spec 6.3 unique key. It does not keep the rule that a redelivered stage reuses its batch context across a circuit close: a batch pinned at epoch e and redelivered after a close is refused as stale (T3) and must re-pin, which gives a new context id for every record of the batch. The circuit state is a pinned input of a decision (I3): a record that reaches an open rule gets a different outcome than it would otherwise, so the epoch makes the dependency explicit and lets replay classify those decisions. Option B needs every caller to supply an ordinal that a crash replay must reproduce, a new source of duplicates. Option C puts an output into an idempotency key, which would turn a nondeterministic re-evaluation into a silent second row and hide an I3 alarm. Epoch 0 is omitted from the canonical form, so every existing context id and digest is unchanged. Costs: a close changes the context id of all later decisions of that pack digest (a few dictionary rows) and of every record of a re-pinned batch; the batch driver that re-pins is P7a and its acceptance test is in the T22 hand-off; the data-quality item and the re-evaluation driver are P3d and P7a hand-offs. **Limit:** `RuleCircuit.epoch()` is process-local; after a restart it is 0, so a close before the restart is invisible and the re-evaluation is a `NOOP_REDELIVERY` again; a pack rollback (P9b) has the same hole. The durable per-pack-digest epoch (table `pack_circuit (pack_digest PK, epoch)`, read when the `RuleCircuit` is created, incremented in the transaction that records the close) is a P3d table and a blocker for closing open item 1.
- **D-L2 Insert first, then compare-and-set the head.** A redelivery must not advance the head; the decision row is inserted with `ON CONFLICT DO NOTHING` and only a new row proceeds to the head update; a lost head update rolls the unit back.
- **D-L3 Constraints, not Java checks.** The adapter relies on `23505` and on affected-row counts; a pre-check in Java would pass the contract while racing on the real store (LF1).
- **D-L4 Fail closed on withdrawal until P3d.** A superseding decision that is not REPORT, or that drops a leg that has versions, throws `WithdrawalRequiredException` in both `commitDecisions` and `commitReportable`; P3d replaces the throw by the 9.3 WITHDRAWN transaction.
- **D-L5 Real-store evidence is gated by mode.** `Gates traceability --realstore skip` (build jobs on both systems) and `--realstore only` (job `ledger-pg`); a cited REAL-STORE test that was skipped is never a pass (LF2, LF3).
- **D-L6 A failure channel without sign-in.** Test tallies per class and failed or errored test cases are re-emitted as workflow annotations (T12), which the unauthenticated check-run listing returns; the agent never downloads artefacts (LF2).
- **D-L7 Plain-SQL migrator, forward-only.** Versioned scripts listed in `index.txt`, SHA-256 per script stored in `schema_migration`, a PostgreSQL advisory lock, every script one transaction, refusal on drift, gap or a newer database. The approved schema document's SHA-256 is recorded and tested (LF13).
- **D-L8 The `ledger-pg` service container uses `trust` authentication**; the container port is published on the runner loopback only; the job runs on GitHub-hosted `ubuntu-24.04` only (`PinCheck` already refuses `-latest` labels) and must never move to a self-hosted runner: no credential exists in any file.

**Section 4 (I1, I2, I6, I9, I10)**

> | I1 | **Durable before effect.** No first byte to a destination, no acknowledgement to a source and no move or delete of a source file happens until the record that justifies it is durable (ledger committed with synchronous-standby acknowledgement, and bytes or journal objects acknowledged by the evidence store as durable, §5.4). The system fails closed. |
> | I2 | **Correctness comes from ledger constraints** (unique keys, partial unique in-flight index, fenced leases), not from messaging semantics or exactly-once claims. |
> | I6 | **Silence is neither success nor failure.** No blind resend. Automatic resend is limited to content the destination provably never processed (not received, or rejected whole at file level). |
> | I9 | **One sender per endpoint.** A lease with a fencing token, expiry and pre-commit re-check narrows the window for a second sender; it cannot close it.
> | I10 | **The evidence tier is never rebuilt; the database is restored from backup and made current from the evidence tier.**

**Sections 5.2, 5.3, 6.3 (ports, stack, decision record)**

> `LedgerStore` is a unit-of-work API: every "same transaction" rule in this document is one call on the port, so the in-memory and PostgreSQL adapters share one invariant suite.
> Database migrations are forward-only (expand/contract).
> | Ledger | PostgreSQL 18, quorum synchronous standby, PITR from base backup plus WAL | Behind the `LedgerStore` port; backups are held by the §5.5 backup tooling, not in the evidence tier |
> Rows carry no personal data and are partitioned by trade date.
> The `decision` table is **insert-only**. A re-evaluation inserts a superseding row with a higher `decision_seq`; the current decision is the highest `decision_seq` of a (`regime`, `event_identity`) chain.
> A decision's unique key is `(event_identity, decision_context_id, input_digest)`, so a redelivered stage, which reuses its batch context (§6.5 step 6), is a no-op.
> PostgreSQL requires every unique index on a partitioned table to contain the partition key, so chain linearity is enforced on an unpartitioned `decision_head(regime, event_identity, decision_seq, decision_id)`, advanced by compare-and-set in the same transaction as the decision insert: the insert fails unless the head's `decision_seq` is the new seq minus 1, and a loser re-reads the head and re-evaluates against the latest inputs.
> The P3 schema design (§11.1) lists every partitioned table and shows how each unique constraint satisfies the partition-key rule, and the invariant suite includes a cross-partition duplicate-seq case (a correction that changes trade date).

**Sections 7.8, 10, 11.1 (outbox, keys, schema design)**

> for REPORT outcomes, the decision row, `report_version`, `delivery` and an outbox row in one synchronous transaction per micro-batch

## Conventions (read before Task 1)

The P0 Conventions 1 to 11, the P1a Conventions 1 to 3 and 7 to 9 and the P2a Conventions 1 to 10 hold (shorthand `MVN`, `T <module> <selector>`, `IT <module> <selector>`, `FMT`, `COMMIT "<message>"`; Bash and PowerShell forms). Deltas:

1. **Branch and commits.** `p3a/ledger-core`; one commit per task (T1 also commits this plan alone first). `COMMIT "<message>"` is `FMT`, `git add -A`, `git commit -m "<message>" -m "Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>"`. `git status --short` before each commit shows only the task's files. Never skip hooks. The owner merges.
2. **Environment.** Every new shell sets `JAVA_HOME` (Bash: `export JAVA_HOME=/c/dev/jdk/jdk-25.0.4.1+1; export PATH="$JAVA_HOME/bin:$PATH"`; PowerShell: `$env:JAVA_HOME='C:\dev\jdk\jdk-25.0.4.1+1'; $env:Path="$env:JAVA_HOME\bin;$env:Path"`). PowerShell 5.1 has no `&&`; quote arguments containing `#`, `,` or `=`. Never use `python3`.
3. **Task steps.** (1) write the named tests (a name is a method; the text after it is its assertion); (2) run them red and see the stated failure; (3) implement the minimum; (4) run green, then the wider run; (5) commit. A test class lives in the package of the class it tests unless stated.
4. **Real-store tests.** `*IT` classes in `regpack-postgres` read `REGPACK_PG_URL` (a JDBC URL without a schema, for example `jdbc:postgresql://127.0.0.1:5432/postgres?user=postgres`). Unset: `Assumptions.abort`, reported as skipped. `REGPACK_PG_REQUIRED=true` with an unset or unreachable URL: failure. Each test works in its own schema. **Locally these are `NOT RUN LOCALLY`: the expected local result of a PostgreSQL IT is `Skipped: <all>` (except a test that needs no server, such as the required-mode test of `PgHarnessIT`)**, and the task's real green is the checkpoint run it names. A task is built at its commit and verified at the next checkpoint; a failure at a checkpoint is a fix round on the task that owns the test. If OI-13 is answered, the `*IT` classes of T11 and T15 to T20 run locally against it, a task is then verified at its commit, and CP-1 to CP-4 become confirmation runs; the checkpoint list and the exit evidence are unchanged.
5. **Reading CI.** The agent reads run, job and annotation listings only. Tally notices (one per test class, with run, failed, errors and skipped counts) and failure annotations (T12) carry the counts, the test name and the first line of the message (cut at 300 characters, credentials redacted); the agent never downloads an artefact and never reads a log.
6. **Constraints are named.** Every constraint and index in `V001` has an explicit name (`CONSTRAINT <name> ...`, `CREATE UNIQUE INDEX <name>`); adapter code maps a violation to its meaning by SQLState and constraint name (`PgErrors`), never by message text.
7. **Time and zones.** Instants go to and from `timestamptz` as `OffsetDateTime` at `ZoneOffset.UTC`; dates for partitions come from `Partitions.dateOf` (the UTC date of `instant.atOffset(ZoneOffset.UTC)`); no `ZoneId.systemDefault()`, no default-locale call in `regpack-postgres` main code (`NoWallClockRandomLocaleTest` scans it for all four rule sets); every unit sets `SET LOCAL TimeZone = UTC` (Convention 11).
8. **Effort ledger.** The controller appends per task to the untracked `.superpowers/p3a-ledger.md`: implementer and reviewer runs, fix rounds, agent minutes (CI and owner waits excluded), subagent tokens, owner minutes, tests added, CI round trips and their wait, commit; for each checkpoint: the time the push was requested, done, the run ended, and the number of red runs before green; it is copied into the exit record (T23).
9. **Stop conditions** (stop and ask): P0 Convention 10, P1a Convention 9 and P2a Convention 9, plus any dependency, plugin, workflow file or image other than AP-5 and AP-6; a change to a port signature other than those in "Port and model changes"; an edit under `spikes/`; `docker` on the development machine; weakening a test, a gate or a constraint to get green; a push or a CI dispatch without AP-2 or AP-8.
10. **Checkpoints do not block.** At a CP the controller states the head to push and asks once. It then continues with the next tasks that do not need the result (CP-1: T14 and T15; CP-2: T18 and T19; CP-3: T22 and T23 steps 1 to 3). It makes no push request while a run is pending. A red run is a fix round as a separate commit on the owning task's files; the next push request names the head that contains all fixes. A task is verified only by the run of a head that contains it.
11. **Units.** Every write unit starts through one package-private prologue `Unit.begin(Connection)`: autocommit off, `READ COMMITTED` set explicitly, `SET LOCAL TimeZone = UTC`, `SET LOCAL lock_timeout` and `statement_timeout` (`Config`; defaults 5 s and 60 s; the capacity probe may raise the latter), `SET LOCAL synchronous_commit = on` (controlled by `Config.forceSynchronousCommit`, default true; only the capacity variant C of T21 sets it false). Rows are locked in one canonical order: decision heads by (`regime_id`, `event_identity`), subjects by (`regime_id`, `event_identity`, `leg`), deliveries by (`endpoint_id`, `business_key`); results are returned in input order. `PgErrors` classes: `40P01` DEADLOCK and `40001` SERIALIZATION (on a `decision_head` update surfaced as `DecisionHeadConflictException` after the rollback and a re-read, otherwise `LedgerException`; the caller retries, the adapter does not); SQLState class `08`, `57P01` to `57P03` and `53300` CONNECTION (always a `LedgerException`: never `false`, never `STATE_MISMATCH`, never an empty `Optional`). `NO_PARTITION` is SQLState `23514` with a null constraint name, never message text.
12. **SQL text and messages.** Every value reaches SQL as a `PreparedStatement` parameter. The only concatenated text is a schema or table identifier, through `SqlIdentifier.require(String)` (pattern `[a-z][a-z0-9_]{0,62}`); `Migrator`, `Partitions`, `LedgerIntegrity`, `PgLedgerStore.Config` and `PgTestDatabase` all use it (`SqlIdentifierTest`). Advisory locks are transaction-level, two-int form `pg_advisory_xact_lock(purpose, hashtext(<schema> [|| ':' || <source id>]))` with purpose 1 migrator, 2 partition, 3 source; session-level advisory locks are not used (so tests in different schemas never share a lock). No `SQLException` message, server DETAIL or HINT, SQL text, bind value or report body reaches a `LedgerException`, `MigrationException`, log line or annotation: `PgErrors.wrap(SQLException)` returns exactly `ledger statement failed: sqlstate=<SQLSTATE> constraint=<name|none>` and keeps the original only as the cause; `MigrationException` carries the script name and version, never SQL text.


**Semantics of `commitReportable`** (normative; the contract tests of T7 are its oracle):

1. All or nothing, including the decisions, which follow `commitDecisions` exactly (idempotency key, head compare-and-set, supersedes link, `completesOutbox`).
2. A `NewVersion` is accepted only for a decision whose outcome is REPORT and for a leg in that decision's `legs`, at most once per (decision, leg); `NewVersion.subject.regime()` and `eventIdentity()` must equal the decision body's regime and event identity; otherwise `IllegalArgumentException` before any write.
3. For a decision that is `NOOP_REDELIVERY`, a requested version that already exists for (decision, subject) returns `EXISTING` and writes nothing; one that does not exist is created only if that decision is still the head of its chain (else `DecisionHeadConflictException`).
4. For an `INSERTED` decision, per `NewVersion`: get-or-create the subject by (regime, event identity, leg); apply rule 5; apply rule 7; create the version with `versionSeq` = last + 1; create the delivery in PREPARED with `NewDelivery(endpoint, endpointEpoch, executingLei + "|" + trn, versionSeq)`.
5. **TRN.** A subject without a TRN needs a proposal; the pair (executing LEI, TRN) must be unused by every other subject, else `TrnConflictException` and nothing is written. A subject with a TRN takes the stored one: a present proposal must equal the stored TRN string and the executing LEI must equal the stored one (else `IllegalArgumentException`); a different key id in the proposal is ignored and the first key id is kept. The TRN, its key id and the assignment instant (the ledger `Clock`) are stored in the same unit as the first version and never change.
6. `versionSeq` is gapless per subject (1, 2, 3 ...) and assigned under the subject's row lock.
7. **Suppression.** If the latest version of the subject whose delivery is not in the dead states {REJECTED, IN_REPAIR, WITHDRAWN, WRITTEN_OFF} has the same `action` and `logicalHash`, the result is `SUPPRESSED_UNCHANGED` and nothing is written in P3a; the journal entry of the suppression (spec 10: suppressed and journalled) is written by P3d in the same unit, because P3d owns the ledger event table. (P3d confirms the dead set against the 9.3 edge list; `FILE_REJECTED` is not dead because it returns to RESEND_PENDING with unchanged content.)
8. **Withdrawal guard.** An `INSERTED` decision whose superseded decision has subjects with at least one version, and whose outcome is not REPORT or whose legs omit a leg that has versions, throws `WithdrawalRequiredException` and writes nothing; `commitDecisions` applies the same rule (D-L4).
9. If `sequenceBatch` is present and at least one version is `CREATED`, one outbox item of kind `SEQUENCE` with `subjectId` = the batch id exists afterwards (an existing one is left; unique on kind and subject).
